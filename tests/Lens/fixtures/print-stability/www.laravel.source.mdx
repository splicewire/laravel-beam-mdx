# Beam on Laravel

Beam is the Laravel framework for SaaS applications on which Splicewire is built. It connects declared data to resource APIs, generated consumers and reusable UI, then lets the host compose accounts, tenancy, workflows, authoring and commerce. A CMS is one application of these mechanisms.

Start with [installation and package combinations](/beam/docs/laravel/adoption), then [build the service desk](/beam/docs/laravel/service-desk). The tutorial supplies the actual application model, input/read DTOs, team scope, policy, mounts and UI wiring; a schema alone does not supply those decisions.

## Choose a track

- **Start:** [install and compose](/beam/docs/laravel/adoption).
- **Build:** [the service desk](/beam/docs/laravel/service-desk) and [application capabilities](/beam/docs/laravel/capabilities).
- **Data sources:** [backings and federation](/beam/docs/laravel/backings).
- **Extend:** [local features, commerce and marketplace boundaries](/beam/docs/laravel/extensions).
- **Reference:** [declarations, generation and package ownership](/beam/docs/laravel/reference).
- **Operate:** [requests, tenancy, diagnostics, releases and file reconciliation](/beam/docs/laravel/operations).
- **Examples:** [UI catalogue](/beam/docs/laravel/ui-catalogue) and [Schemastud's independent examples](https://schemastud.io/docs/examples).

Schemastud owns schema projection, Seam editing/widgets and Frame resource/UI contracts. Beam owns SaaS composition and federation above those contracts. Splicewire owns its product engines and hosted integrations. Follow the owning reference rather than treating the product's deployment as a framework prerequisite.
